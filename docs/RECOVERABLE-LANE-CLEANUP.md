# Recoverable lane cleanup

Recoverable cleanup routes historical dormant-preservation journals by their
exact selected worktree subject before validating the full journal. Unrelated
historical journals therefore cannot block a clean lane's cleanup plan merely
because their embedded controller paths have become stale.

A journal that selects the cleanup target by worktree path, branch, head SHA,
and tree SHA is still normalized completely. Malformed JSON, ambiguous subject
records, and malformed target-matching journals fail closed. Cleanup continues to require terminal
local and remote authority, an exact plan authorization, a verified Git bundle,
durable worktree and Git-directory snapshots, and non-force removal.

A clean detached worktree is eligible only when it has no local branch, remote
branch, writer lease, or cloud claim and at least one completed dormant-preservation
journal selects its exact path, null branch, HEAD, and tree. The cleanup plan must
supersede every such receipt. Its recovery bundle records `HEAD` as the preserved
tip, the transient cleanup reservation uses an internal non-ref registry identity,
and the controller never creates, attaches, updates, or deletes a Git ref. Attached
lane behavior and historical evidence remain unchanged.

## Ignored generated residue

A terminal lane may contain ignored generated output only when its complete
ignored inventory resolves to the exact repository profile `node_modules/` and
`web/dist/`. The planner seals the ignored paths, every generated entry and
byte, and the complete checkout inventory. Missing roots, additional ignored
paths, symlinks at either root, unsupported filesystem entries, or byte drift
fail closed before the worktree registration is removed.

Every empty directory outside those roots is residue and is rejected whether
Git ignores it or not. Descendant symlinks are accepted only when relative and
their complete resolution chain remains inside ordinary checkout paths; this
preserves npm `.bin` links while rejecting absolute, escaping, and indirect
symlink escapes.

The generated directories are preserved inside the same durable checkout
quarantine as the tracked tree. They are not deleted in place, treated as
disposable, or excluded from the recovery receipt. A lane without ignored
output continues to use the explicit `none` profile.

Evidence v2 owns this generated-residue projection. The normalizer retains a
read-only v1 branch so previously completed cleanup intents and receipts remain
verifiable without inventing residue evidence; only newly planned cleanup uses
v2.

If generated bytes drift after the checkout has moved but before quarantine is
sealed, the controller restores the exact worktree registration, journals
`drift_aborting`, releases only its exact reservation, and seals
`drift_aborted`. Response-loss replay rechecks the restored checkout and the
released reservation; it never reports an abort after either state changes.
